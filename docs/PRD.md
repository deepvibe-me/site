# deepvibe PRD v2 — 구현 명세

> **문서 목적:** 이 문서 하나로 디자이너·개발자가 deepvibe를 처음부터 끝까지 구현할 수 있게 한다.
> **기준:** 현재 랜딩 페이지(`index.html`)의 디자인과 문구는 **그대로 유지**한다. 아직 정해지지 않은 부분은 디자인을 해치지 않는 선에서 **[제안]**으로 안을 낸다.
> **표기:** [확인] = 랜딩 페이지에 이미 있는 사실 · [제안] = 이 문서가 내는 안 · [결정 필요] = 사업 판단이 필요한 항목

| 항목 | 내용 |

## 1. 배경과 문제

### 1.1 사용자가 겪는 문제 [제안]
1. **"지금 뭘 해야 하지?"를 물어볼 데가 없다.** 친구 조언은 편향되고, 커뮤니티 글은 맥락을 모른다.
2. **카톡에는 답이 이미 있다.** 답장 속도, 먼저 말 거는 비율, 대화가 끊기는 시점 같은 패턴은 대화에 다 남아 있지만 혼자서는 읽어 내기 어렵다.
3. **기존 매칭 앱은 프로필만 본다.** 사진·직업·키로는 "대화가 잘 통하는지"를 알 수 없고, 스와이프 피로가 크다.

### 1.2 최근 소비자 흐름과 반영 방향 [제안]
| 흐름 | deepvibe 반영 |
|---|---|
| 성향 테스트(MBTI 이후 "나를 설명하는 언어")에 대한 꾸준한 수요 | 분석 결과를 **"결 프로필"**이라는 6축 성향으로 요약하고, 공유 카드로 만든다 |
| 스와이프 피로, 느린 데이팅(slow dating) 선호 | 매칭은 **주 2회, 1명씩**만 소개한다. 목록 탐색 UI를 두지 않는다 |
| 구독 피로, 투명한 비용 선호 | 월 구독 대신 **이용권 단건 결제**. 차감 시점을 화면에 명시한다 |
| 개인정보 민감도 상승 (특히 대화 데이터) | 원본 즉시 삭제를 **화면에서 보여 주는** 흐름(삭제 완료 표시)으로 만든다 |
| AI 연애 코칭·답장 도우미 사용 증가 | 리포트의 "추천 행동"에 **바로 보낼 수 있는 문장**을 넣는다. 3차에서 답장 코치 기능 추가 |
| 안전 검증 요구(매칭) | 매칭 트랙은 휴대폰 본인 인증을 필수로 한다 |

## 2. 목표와 지표

### 2.1 목표 [제안]
- **MVP(1차):** 카톡 파일 업로드부터 리포트 열람까지 **3분 안에**, 결제 포함 이탈 없이 끝나는 흐름을 만든다.
- **2차:** 혼자 트랙 사용자가 **첫 소개 카드를 받아 수락하는 비율 30%** 이상.

### 2.2 핵심 지표 [제안]
| 단계 | 지표 | 목표 |
|---|---|---|
| 사전 등록 | 랜딩 방문 → 카카오 채널 친구 추가 전환율 | 15% |
| 가입 | 채널 친구 → 가입 전환율 (오픈 알림 발송 후 7일) | 25% |
| 활성화 | 가입 → 첫 리포트 열람 | 60% |
| 업로드 품질 | 파일 파싱 실패율 | < 3% |
| 성능 | 업로드 완료 → 리포트 열람 p95 | ≤ 180초 |
| 만족 | 리포트 하단 "도움이 됐어요" 비율 | ≥ 70% |
| 수익 | 무료 미리보기 → 이용권 구매 전환율 | 20% |
| 재방문 | 30일 내 재분석 비율 | 25% |
| 매칭 | 소개 카드 수락률 / 상호 수락률 | 30% / 10% |

## 3. 사용자와 트랙

### 3.1 주 사용자 [제안]
- 카카오톡을 주로 쓰는 한국의 20대 중반 ~ 30대 중반.
- 모바일 웹(카카오톡 인앱 브라우저 포함)에서 접속하는 비율이 80% 이상일 것으로 가정한다. → **앱 스토어 출시 없이 모바일 웹 + PWA로 시작**한다.

### 3.2 트랙별 제공 가치 [확인] 와 리포트 구성 [제안]

| 트랙 | 랜딩 문구 [확인] | 리포트가 답하는 질문 [제안] |
|---|---|---|
| 사귀는 중 | 무엇부터 바꾸면 되는지 | 지금 관계의 온도는? 반복되는 갈등 패턴은? **가장 먼저 바꿀 한 가지**는? |
| 썸 타는 중 | 다음에 뭘 하면 되는지 | 상대 신호는 어떻게 읽히나? 지금 몇 단계인가? **다음 한 걸음**은 무엇이고 어떤 말로 하나? |
| 혼자 | 결이 맞는 사람 소개 | 내 결은 어떤 모양인가? 어떤 결의 사람과 맞나? 이번 주 소개는 누구인가? |

## 4. 전체 사용자 흐름

```
[랜딩 /]
  └ 오픈 전: "오픈 알림 받기" → 카카오 채널 (현재)
  └ 오픈 후: "시작하기" → [/start 카카오 로그인]
                              └ [/onboarding 트랙 선택 + 동의]
                                   ├ 사귀는 중 / 썸 → [/upload 파일 업로드]
                                   │      └ [/analysis/:id 분석 중 → 원본 삭제 표시]
                                   │             └ [/report/:id 무료 미리보기]
                                   │                    └ 이용권 사용 → 풀 리포트
                                   │                           └ (이용권 없음) [/credits 구매]
                                   └ 혼자 → [/profile 결 프로필 만들기]
                                            └ [/match 이번 주 소개 카드]
                                                   └ 수락/보류 → 상호 수락 → [/match/:id 대화]
[/me 마이페이지: 이용권, 기록, 데이터 삭제]
```

## 5. 화면 명세

모든 화면은 랜딩 페이지와 같은 틀을 쓴다: 배경 `--bg`, 최대 폭 **440px**, 좌우 패딩 20px, 가운데 정렬, Pretendard 본문, 제목은 26px/600, 포인트 세리프는 Fraunces. [확인]

### 5.0 공통 컴포넌트

기존 클래스를 그대로 재사용하고, 부족한 것만 추가한다.

| 컴포넌트 | 출처 | 사양 |
|---|---|---|
| `.badge` 상태 배지 | 기존 | 13px, `--muted`, 둥근 테두리. 화면 상단 문맥 표시에 쓴다 ("1/3 단계", "분석 중") |
| `.src .row` 아이콘 행 | 기존 | 36px 흰 아이콘 박스 + 제목(15px/600) + 설명(13px muted). 옵션·입력 항목에 쓴다 |
| `.tracks` 리스트 카드 | 기존 | 흰 배경, 1px `--l08` 테두리, radius 20px, 행 사이 구분선. 선택 목록·요약 목록에 쓴다 |
| `.cta` 주 버튼 | 기존 | 높이 56px, radius 16px, 700. **카카오 노랑은 카카오 관련 동작에만** 쓰고, 일반 주 버튼은 `--ink` 배경 + 흰 글자로 추가한다 (`.cta.dark`) [제안] |
| `.cta.ghost` 보조 버튼 [제안] | 신규 | 투명 배경, 1px `--l12` 테두리, `--ink2` 글자 |
| 진행 바 [제안] | 신규 | 높이 6px, `--soft` 트랙, 채움은 `--pink`→`--violet` 선형 그라데이션 |
| 온도 게이지 [제안] | 신규 | 반원 게이지, 같은 그라데이션. 가운데 숫자는 Fraunces 44px |
| 결 레이더 [제안] | 신규 | 6축 레이더. 선은 `--violet`, 채움은 `--violet` 12% |
| 바텀시트 [제안] | 신규 | 흰 배경, 상단 radius 24px, 뒤는 `rgba(20,10,30,.4)` 딤. 이용권 사용 확인·공유에 쓴다 |
| 토스트 [제안] | 신규 | `--ink` 배경, 흰 13px 글자, 하단 24px, 2.5초 |
| 입력 필드 [제안] | 신규 | 높이 52px, `--soft` 배경, radius 14px, 포커스 시 1px `--violet` |

접근성: 모든 아이콘 버튼에 `aria-label`, 포커스 링은 `--violet` 2px, 색 대비는 본문 4.5:1 이상 유지. 랜딩 페이지가 이미 `aria-label`을 쓰고 있으므로 같은 수준을 지킨다. [확인]

### 5.1 `/` 랜딩 [확인 + 오픈 후 변경안]
- 현재 페이지를 그대로 쓴다.
- 오픈 후에는 두 곳만 바꾼다 [제안]:
  - `.badge`: "AI 관계 분석 · 오픈 준비 중" → "AI 관계 분석"
  - `.cta`: "오픈 알림 받기"(카카오 채널) → "카카오로 시작하기"(`/start`). 카카오 노랑 유지.
  - `.reward`: "오픈 전 친구 추가하면 이용권" → "첫 결 미리보기는 무료"
- 나머지 문구, 섹션, SNS, 푸터는 변경하지 않는다.

### 5.2 `/start` 로그인
- 로고(120px) + "카카오로 시작하기" 카카오 버튼 하나.
- 아래 13px `--muted`: "로그인하면 이용약관과 개인정보처리방침에 동의한 것으로 봐요" + 링크.
- 로그인 성공 → 가입 여부에 따라 `/onboarding` 또는 마지막 화면으로.

### 5.3 `/onboarding` 트랙 선택과 동의
1. **트랙 선택:** `.tracks` 카드를 그대로 쓰되 각 행을 선택 가능하게 한다. 선택된 행은 왼쪽 라벨 색(핑크/보라)으로 2px 왼쪽 테두리가 생긴다.
2. **동의 (필수 2 + 선택 1):**
   - [필수] 내가 올리는 대화에 포함된 **상대방의 메시지**는 분석에만 쓰이고 저장되지 않는다는 점을 이해했어요
   - [필수] 분석 결과(파생 정보)는 내 계정에 보관되고, 언제든 삭제할 수 있어요
   - [선택] 분석 품질 개선을 위해 익명화된 통계(메시지 내용 제외)를 쓰는 데 동의해요
3. 혼자 트랙을 고르면 **휴대폰 본인 인증** 단계가 추가된다 (5.10).

### 5.4 `/upload` 파일 업로드
- 상단 `.badge` "1/3 파일 올리기".
- **안내 카드 (`.src` 재사용):** "카톡 대화 내보내기 방법" — 아이폰/안드로이드/PC 탭. 각 탭에 3단계 스크린샷 텍스트.
- **드롭존:** `.tracks` 카드 안에 점선 테두리 영역. "파일 선택" `.cta.dark`. 허용: `.txt`, `.csv`, `.zip`(내보내기 압축). 최대 20MB.
- 파일 선택 즉시 **브라우저에서** 1차 파싱(헤더·참여자 수·기간)을 해서 보여 준다:
  - 참여자 2명 확인 → "나는 누구인가요?" 라디오 (이름 2개)
  - 참여자 3명 이상 → "1:1 대화만 분석할 수 있어요" 오류 (단체방 미지원)
  - 기간 표시: "2025.03.02 ~ 2026.10.30 · 메시지 18,420개"
- **상대 정보 (최소):** 상대와의 관계는 트랙으로 이미 정해졌으므로 묻지 않는다. 썸 트랙만 "알게 된 지" 선택(1개월 미만 / 1~3개월 / 3개월 이상)을 받는다 [제안].
- 하단 고정 `.cta.dark` "분석 시작" + `.trust` 문구 "분석이 끝나면 원본은 바로 지워져요" [확인].

### 5.5 `/analysis/:id` 분석 중
- 로고가 천천히 숨 쉬듯 커졌다 작아지는 애니메이션(scale 1 → 1.04, 2.4s).
- 진행 바 + 단계 문구 (서버 상태를 3초마다 폴링):
  1. "대화를 읽고 있어요" (파싱)
  2. "패턴을 찾고 있어요" (통계)
  3. "결을 해석하고 있어요" (LLM)
  4. **"원본을 지웠어요 ✓"** — 삭제 완료 시점을 사용자에게 명시적으로 보여 준다 [제안]
- 예상 시간 "보통 1~2분 걸려요". 화면을 닫아도 되며, 끝나면 카카오 알림톡을 보낸다 (8.6).

### 5.6 `/report/:id` 리포트
**무료 미리보기 영역 (항상 보임)** [제안]
- 온도 게이지 + 한 줄 요약 (예: "서로 리듬은 잘 맞는데, 깊은 얘기를 피하고 있어요")
- 결 레이더 (내 결 6축)
- 블러 처리된 아래 섹션 위에 바텀시트 트리거 `.cta.dark` "이용권 1장으로 전체 보기" / 이용권 없으면 "이용권 구매하기"

**풀 리포트 (이용권 사용 후)**
- 공통
  - **대화 리듬:** 먼저 말 건 비율, 평균 답장 시간(나/상대), 시간대 히트맵(요일×시간)
  - **결 비교:** 나와 상대의 6축 레이더 겹쳐 보기 + 축별 한 줄 해석
  - **강점 3가지 / 긴장 지점 3가지** — 각 항목에 근거가 되는 패턴을 숫자로 적는다 (예: "최근 4주 상대의 답장 시간이 평균 12분 → 41분으로 늘었어요")
- 사귀는 중 트랙
  - **반복되는 갈등 패턴** 1~2개 (발생 주기, 시작 트리거, 마무리 방식)
  - **가장 먼저 바꿀 한 가지** + 이번 주 실천 체크리스트 3개
  - **대화 스크립트:** 실제로 보낼 수 있는 문장 3개 (톤: 부드럽게 / 솔직하게 / 가볍게)
- 썸 트랙
  - **지금 단계** (1 탐색 → 2 호감 → 3 확인 → 4 전환 → 5 결정) + 근거
  - **상대 신호 해석** 긍정/중립/주의 3개
  - **다음 한 걸음** + 바로 보낼 수 있는 메시지 3안
- 하단
  - "도움이 됐어요 / 아쉬워요" 피드백 (지표 2.2)
  - "결과 카드 공유" (3차) · "30일 뒤 다시 분석하기" 리마인더 신청 (3차)
  - 작은 글씨: "이 리포트는 대화 패턴에 기반한 참고 정보예요. 중요한 결정은 직접 하세요."

### 5.7 `/credits` 이용권
- `.tracks` 카드로 상품 3개 나열 (9장). 선택 시 왼쪽 테두리 강조.
- 결제 버튼 `.cta.dark` "결제하기" → 토스페이먼츠 결제창.
- 결제 완료 → 직전 화면으로 돌아가 자동으로 리포트를 연다.

### 5.8 `/me` 마이페이지
- 보유 이용권, 분석 기록(날짜·트랙·온도), 결 프로필, 연결된 서비스(구글), 약관.
- **"내 데이터 모두 삭제"**: 바텀시트에서 한 번 더 확인 → 즉시 삭제, 계정 탈퇴 포함. 삭제 후 30일 보관 없이 바로 지운다 [제안].

### 5.9 `/profile` 결 프로필 만들기 (혼자 트랙)
입력 3가지 중 **최소 1가지** 필요하며, 많을수록 프로필 신뢰도 배지가 올라간다 [제안].
1. **카톡 대화 업로드** — 친한 친구나 과거 연인과의 1:1 대화. 동의 문구는 5.3과 같다.
2. **12문항 결 설문** — 6축 × 2문항, 각 5점 척도. 2분 소요. 파일이 없어도 시작할 수 있게 하는 대체 입력.
3. **유튜브·캘린더 연결** (3차) — 관심사 태그와 생활 리듬.

결과: 결 레이더 + 결 유형 이름(예: "느긋한 직진형") + 관심사 태그 + "이런 결과 잘 맞아요" 한 줄.

### 5.10 본인 인증과 소개 설정 (혼자 트랙)
- 휴대폰 본인 인증(PASS/통신사) 필수. 성별·출생연도는 인증 결과에서 받고 수정할 수 없다 [제안].
- 소개 설정: 찾는 성별, 나이 범위(기본 ±5세), 지역(시/도, 복수), 사진 1~3장(선택이지만 사진이 있는 사람끼리 우선 매칭).
- 자기소개는 쓰지 않는다. **결 프로필이 자기소개를 대신한다** — 이것이 서비스의 차별점이므로 UI에서 강조한다.

### 5.11 `/match` 이번 주 소개
- 상단 `.badge` "이번 주 소개 · 월·목 도착".
- **소개 카드 1장:** 사진(있으면, 없으면 결 유형 일러스트), 결 유형 이름, 나이대·지역, **두 결이 맞는 이유 3줄**(LLM 생성), 겹치는 관심사 태그.
- 버튼: `.cta.dark` "대화해 보고 싶어요" / `.cta.ghost` "이번엔 보류".
- 수락 시 이용권 차감은 **상호 수락 시점**에만 한다 (5.12). 수락 전 바텀시트에 이 사실을 명시한다.
- 카드가 없는 날: "다음 소개는 목요일 오전 10시에 도착해요".

### 5.12 `/match/:id` 대화
- 상호 수락 시 열리는 간단한 1:1 대화방(텍스트만). 첫 메시지 추천 문장 3개를 LLM이 결 프로필로 만들어 준다.
- 상단 메뉴: 신고 / 차단 / 연락처 공유(양쪽이 모두 누르면 카카오톡 ID 공개).
- 14일간 메시지가 없으면 자동 종료.

### 5.13 `/legal/terms`, `/legal/privacy`
- 이용약관, 개인정보처리방침. 개인정보처리방침에는 **원본 즉시 삭제, 제3자(대화 상대) 정보 처리 근거, 파생 데이터 보관 기간, 국외 이전(LLM API)**을 명시한다. 법률 검토 필요 [결정 필요].

## 6. 카카오톡 대화 파일 파싱 명세

### 6.1 지원 형식 [제안 — 실제 내보내기 파일로 검증 필요]
| 출처 | 확장자 | 줄 형식 예 |
|---|---|---|
| Android | `.txt` | `2026년 3월 5일 오후 9:12, 홍길동 : 메시지` |
| iOS | `.txt` | `2026. 3. 5. 오후 9:12, 홍길동 : 메시지` |
| PC(Windows/Mac) | `.txt` | 날짜 구분줄 `--------------- 2026년 3월 5일 목요일 ---------------` 뒤에 `[홍길동] [오후 9:12] 메시지` |
| PC | `.csv` | `Date,User,Message` 헤더 |
| 모바일 압축 | `.zip` | 위 txt가 들어 있음. 사진 등 첨부는 무시 |

- 인코딩: UTF-8 우선, 실패 시 CP949(EUC-KR) 재시도.
- 형식 자동 감지: 첫 50줄에서 각 형식의 정규식 매칭 수를 세어 가장 많은 것을 채택.
- 여러 줄 메시지: 날짜 패턴으로 시작하지 않는 줄은 직전 메시지에 이어 붙인다.

### 6.2 제외·정규화 규칙
- 시스템 메시지 제외: `님이 들어왔습니다`, `님이 나갔습니다`, `삭제된 메시지입니다`, `저장한 날짜 :` 헤더.
- 미디어 메시지는 **종류만 남긴다**: `사진`, `동영상`, `이모티콘`, `파일`, `음성메시지`, `송금` → `media:photo` 등. 통계에서 "미디어 비율"로 쓴다.
- URL은 `url` 토큰으로 치환.
- **민감정보 마스킹(LLM 전송 전):** 휴대폰 번호, 계좌번호, 주민번호 패턴, 이메일, 상세 주소(동/호 패턴) → `[masked]`.
- **이름 가명화:** 참여자 이름은 LLM에 `나` / `상대`로만 전달. 메시지 본문에 나오는 이름도 두 참여자 이름과 같으면 치환.

### 6.3 제한
- 1:1 대화만. 참여자 3명 이상이면 거부.
- 메시지 50,000개 초과 시 **최근 12개월**만 사용하고 리포트에 표시.
- 메시지 200개 미만이면 "아직 대화가 적어서 결을 읽기 어려워요" 안내 후 **이용권을 차감하지 않고** 간이 결과만 제공.

### 6.4 테스트
- 형식별 고정 샘플(fixture) 4종 + 다중 줄, CP949, 단체방, 빈 파일 케이스.
- 파싱 성공률을 지표로 기록(2.2).

## 7. 분석 엔진 명세

### 7.1 파이프라인
```
업로드(Storage, 임시) → 파싱 → 통계 특징 추출 → 대화 샘플 구성 → LLM 해석(JSON)
    → 리포트 저장 → 원본 삭제 → 알림
```
각 단계는 `analyses.status`에 기록하고 화면(5.5)이 폴링한다.

### 7.2 통계 특징 (결정적 계산, LLM 없이)
| 특징 | 계산 |
|---|---|
| 기간, 총 메시지, 일평균 | 기본 |
| 먼저 말 건 비율 | 직전 메시지로부터 **6시간** 이상 지난 뒤 보낸 메시지를 "대화 시작"으로 본다 |
| 답장 시간 | 상대 메시지 뒤 내가 보낸 첫 메시지까지의 시간. 중앙값과 p75, 최근 4주 vs 이전 비교 |
| 미응답률 | 대화 시작 메시지에 12시간 내 답이 없는 비율 |
| 메시지 길이 비율 | 글자 수 중앙값, 나/상대 |
| 질문 비율 | `?` 또는 의문형 어미(`~니`, `~나`, `~까`, `~어?`) 비율 |
| 감정 표현 | `ㅋㅋ`, `ㅎㅎ`, `ㅠㅠ`, 이모지, 이모티콘 비율. 감성 사전(KNU 한국어 감성사전) 기반 긍/부정 점수의 주별 추이 |
| 시간대 히트맵 | 요일 × 시간 |
| 약속 언급 | `만나`, `보자`, `언제`, `주말`, `시간 돼` 등 키워드 주별 빈도 |
| 미래 언급 (썸) | `다음에`, `나중에`, `같이`, `우리` 빈도 |
| 호칭 변화 | 상대가 나를 부르는 호칭 변화 시점(이름→애칭 등) |
| 대화 끊김 | 48시간 이상 공백 횟수와 그 직전 메시지 |

### 7.3 결 프로필 6축 [제안]
각 축 0~100. 통계 특징 + LLM 판단을 7:3으로 합산한다.

| 축 | 0쪽 | 100쪽 | 주요 근거 |
|---|---|---|---|
| 표현 | 은근하게 | 직접적으로 | 감정어 직접 표현 비율, 질문 비율 |
| 템포 | 여유롭게 | 즉각적으로 | 답장 시간 중앙값 |
| 주도 | 따라가는 | 이끄는 | 먼저 말 건 비율, 약속 제안 비율 |
| 깊이 | 가볍게 | 깊게 | 메시지 길이, 감정·고민 어휘 비율 |
| 애정 | 행동으로 | 말로 | 애정 표현 어휘, 이모티콘 비율 |
| 갈등 | 피하는 | 마주하는 | 부정 감정 뒤 대화 지속 여부, 공백 발생 패턴 |

매칭 호환 점수(2차): 템포·주도는 **보완**(차이가 중간일 때 높음), 표현·깊이·갈등은 **유사**(차이가 작을 때 높음), 애정은 가중치 낮음. 가중합 0~100.

### 7.4 LLM 해석
- 모델: Claude API. 기본 `claude-sonnet-5-5`, 품질 비교 후 조정 [제안].
- 입력: (1) 7.2 통계 요약 JSON, (2) 대화 샘플 — 최근 30일 전체 + 이전 기간에서 "대화 시작" 전후 10개씩 샘플, 합계 약 30k 토큰 이내, (3) 트랙과 "알게 된 지".
- 출력: **구조화된 JSON**(스키마 고정, 아래). 자유 서술은 각 필드의 문자열 안에서만.
- 프롬프트 원칙: 근거 없는 단정 금지, 각 해석에 통계 근거 1개 이상 인용, 상대를 비난하지 않는 톤, 메시지 문장은 존댓말/반말을 대화에서 감지해 맞춘다.
- 안전: 폭력·스토킹·자해 징후가 감지되면 리포트 대신 **상담 안내 화면**을 띄운다(한국생명의전화 1588-9191, 여성긴급전화 1366 등). 이 판단은 LLM 출력 `safety_flag`로 받는다.

```json
{
  "temperature": 0-100,
  "one_liner": "string",
  "vibe_axes": {"expression":0-100,"tempo":0-100,"lead":0-100,"depth":0-100,"affection":0-100,"conflict":0-100},
  "partner_axes": {...같은 구조...},
  "strengths": [{"title":"","evidence":""} x3],
  "tensions": [{"title":"","evidence":""} x3],
  "track": {
    "dating": {"conflict_patterns":[{"trigger":"","cycle":"","ending":""}],"first_change":"","checklist":["","",""],"scripts":[{"tone":"soft|honest|light","text":""} x3]},
    "crush":  {"stage":1-5,"stage_reason":"","signals":[{"type":"positive|neutral|caution","text":""} x3],"next_step":"","messages":["","",""]}
  },
  "safety_flag": null | "self_harm" | "abuse" | "stalking"
}
```

### 7.5 비용·성능 목표 [제안]
- 분석 1건당 LLM 비용 ≤ 300원, 전체 처리 p95 ≤ 180초.
- 동일 파일 재업로드(해시 일치) 시 24시간 내에는 재분석하지 않고 기존 리포트를 연다.

### 8.5 원본 삭제 보장 (핵심 약속의 구현) [제안]
1. 업로드는 서명 URL로 Storage에만 간다. 앱 서버 디스크에 쓰지 않는다.
2. 워커는 파일을 **메모리에서만** 읽어 파싱한다.
3. 리포트 저장 트랜잭션 커밋 직후 Storage 객체를 삭제하고 `raw_deleted_at`을 기록한다. 화면 5.5의 "원본을 지웠어요 ✓"는 이 값으로 표시한다.
4. 분석 실패 시에도 즉시 삭제한다. 재시도는 사용자가 다시 올린다.
5. 안전망: 10분마다 `raw` 버킷에서 생성 60분 지난 객체를 삭제하는 크론.
6. 로그·오류 추적에 메시지 본문을 남기지 않는다(길이·개수만).
7. LLM API는 학습에 쓰지 않는 상용 API 조건을 확인하고 개인정보처리방침에 국외 이전으로 명시한다.
8. 사용자 전체 삭제 요청 시 `reports`, `vibe_profiles`, `matches` 등 파생 데이터도 즉시 하드 삭제. 결제 기록만 전자상거래법상 5년 보관(개인 식별자 분리).

## 9. 이용권과 결제 [제안]

### 9.1 원칙
- 월 구독 없음. 이용권 1장 = 리포트 1개 열기 또는 소개 1건 성사.
- 차감 시점을 항상 화면에 먼저 보여 준다.
- 무료 미리보기(온도 + 한 줄 + 내 결 레이더)는 **횟수 제한 없이 무료**. 전환 장치이자 바이럴 장치.

### 9.2 상품안 [결정 필요 — 아래는 제안]
| 상품 | 가격 | 장당 |
|---|---|---|
| 이용권 1장 | 4,900원 | 4,900원 |
| 이용권 3장 | 12,900원 | 4,300원 |
| 이용권 7장 | 24,900원 | 3,557원 |

- 사전 등록 혜택: 카카오 채널 친구에게 **이용권 1장** [확인]. 지급 방식: 오픈 알림톡에 담긴 1회용 코드 입력 [제안].
- 매칭: 소개 카드를 보고 수락하는 것은 무료. **상호 수락이 되어 대화방이 열릴 때** 양쪽에서 각 1장 차감.
- 환불: 열기 전 미사용 이용권은 7일 내 전액 환불. 연 리포트는 환불 불가(디지털 콘텐츠 고지).

### 11.1 M3 기능 상세 [제안]
- **재분석 비교:** 같은 상대의 두 리포트를 온도·6축·답장 시간 변화로 비교. "바꾸기로 한 한 가지"가 실제로 바뀌었는지 보여 준다.
- **답장 코치:** 상대 메시지 1~5개를 붙여 넣으면 결 프로필 기준으로 답장 3안을 준다. 이용권 1장으로 10회. 입력은 저장하지 않는다.
- **공유 카드:** 온도·결 유형·한 줄 요약만 담은 세로 이미지. 상대 정보는 넣지 않는다. 랜딩 유입 UTM 포함.
- **구글 연동:** 유튜브 구독·좋아요 카테고리 → 관심사 태그, 캘린더 일정 밀도 → 생활 리듬(아침형/저녁형, 주말 활동량). 원본 목록은 저장하지 않고 태그·점수만 저장.
